# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static, no-build marketing/demo site for "FundReady AI" — a fictional Vietnamese fundraising-readiness platform concept (also referenced as "BizRaise" in source docs). It is a demo/pitch artifact, not a production app: there is no backend, no data persistence, and no real AI. All content is in Vietnamese (`lang="vi"`).

The repo is two self-contained HTML files plus a Vercel config:

- `index.html` — marketing landing page (hero, problem statement, 6-module solution overview, scoring framework, compliance/risk section, audience segments, final CTA).
- `danh-gia.html` — the combined "Bài đánh giá sẵn sàng gọi vốn" tool, served at the clean URL `/danh-gia`. This single page holds **two integrated scoring engines that feed each other** (see below): a qualitative 8-criteria readiness estimate, and a quantitative 6-category financial calculator that does real, deterministic, formula-based math from user-entered figures — no randomness, no AI call in that half.
- `vercel.json` — sets `"cleanUrls": true` so `danh-gia.html` is reachable as `/danh-gia` (and `index.html` as `/`). Deployed on Vercel (see `.vercel/project.json` for project linkage; that directory is gitignored).

There is no `package.json`, no bundler, no dependency manager, and no test suite. Each HTML file is fully self-contained: CSS in a `<style>` block in `<head>`, JS in inline `<script>` tags at the bottom.

A prior iteration of this repo had the financial calculator as a separate page (`phan-tich-tai-chinh.html`, linked as `/phan-tich-tai-chinh`). It was merged into `danh-gia.html` because the two tools are meant to work together (see "How the two engines connect" below) — don't recreate it as a standalone page; `index.html`'s links point to `/danh-gia#phan-tich-tai-chinh` (an anchor mid-page), not a separate URL.

## Development workflow

No build/install/lint/test commands exist for this project. To work on it:

- Edit `index.html` or `danh-gia.html` directly.
- Preview by opening the file in a browser, or serve locally with any static file server, e.g. `python3 -m http.server` from the repo root — then visit `/index.html` and `/danh-gia.html` directly (the `cleanUrls` rewrite only applies on Vercel, not a plain static server).
- Deploy via Vercel (`vercel deploy` / `vercel --prod` if the Vercel CLI is installed, or through the linked Vercel project).

Since there's no framework, sanity-check changes by actually opening the page in a browser — there's no compiler or type system to catch mistakes. `danh-gia.html` in particular has many `document.getElementById` calls with hand-maintained IDs (many deliberately prefixed `fin*` to avoid colliding with the general-assessment half's IDs of the same shape — e.g. `finGaugeArc` vs `gaugeArc`, `finRiskList` vs `riskList`); a typo'd ID fails silently at runtime with no build-time warning, so click through both halves after any edit near IDs.

## Architecture / conventions shared across both pages

Both HTML files duplicate the same design system rather than sharing a stylesheet — **when changing shared visual language (colors, spacing, components), update both files**. Key shared conventions:

- **Design tokens** live in a `:root` CSS custom-property block at the top of each `<style>`: colors via `oklch()`, a light "surface" palette plus a `--deep*` dark-band palette (used for header, hero, compliance section, result panels), an `--accent` (amber/gold) color, and five `--r1`..`--r5` rating colors used for the 0–100 readiness scale (red → amber → yellow → teal → deep green).
- **Fonts**: "Be Vietnam Pro" (display/body) and "IBM Plex Mono" (numeric/mono, class `.num`), loaded from Google Fonts.
- **The 0–100 score and 5-tier scale** (`TIERS`, defined once in `danh-gia.html`) is the central domain concept, reused by *both* scoring engines on the page (see below) and mirrored in the scoring-weights table on `index.html` (`#scoring`) and its `.rating-labels`/`.scale-legend` markup, which are static HTML there, not generated from JS.
- **Animation**: GSAP loaded from a CDN (cdnjs, with SRI hashes) — used for scroll-reveal, a word-mask hero title split, magnetic-pull buttons, and 3D tilt on result panels (`.result-panel`, applied via `querySelectorAll` since `danh-gia.html` has two of them). All motion is gated behind `window.matchMedia('(prefers-reduced-motion: reduce)')` checks; new animations should follow the same guard pattern.
- **SVG icons** are hand-authored inline (no icon library/sprite sheet).

## `danh-gia.html`: two scoring engines that connect

This page holds two conceptually different scoring engines merged into **one compact result surface** — not two tools placed on the same URL, and not two results stacked one after another. Picking a sample profile (or entering real numbers) drives both engines from a single input flow, and they render into shared panels (one result card, one expert-note, one report grid) with each half referencing the other's number. Read both sub-sections before editing either.

### Engine 1 — document-by-document readiness score (Bước 1–2)

Rebuilt around two real reference frameworks: "Bộ tiêu chí đánh giá sức khỏe doanh nghiệp" (the original 8 pitch/financial-narrative documents) and a second criteria doc ("BÔ TIÊU CHÍ.md") covering cap-table/legal/product-data due diligence, merged into **one 16-document rubric**. The model scores **16 individual fundraising documents** — Hồ sơ giới thiệu, Pitch Deck, Executive Summary, Kế hoạch kinh doanh, Pháp lý & Tài chính, Hồ sơ pháp lý, Báo cáo tài chính, Dự báo tài chính, Cap Table, Hợp đồng cổ đông, Danh sách cổ đông, Sản phẩm và khách hàng, Hồ sơ sở hữu trí tuệ, Dữ liệu sản phẩm, Dữ liệu khách hàng, Kế hoạch sử dụng vốn — each against its own faithfully-transcribed weighted rubric (main criteria + a/b/c sub-criteria), then rolls those up into one overall score. Simulates an AI document-analysis flow entirely client-side — **no data ever leaves the browser**.

- `DOC_RUBRICS` (top of script): one entry per document type — `key`, `name`, `docWeight` (its contribution to the overall 100-pt score), `criteria[]` (each with `name`, `w` out of that document's own 100, and `sub[]` reference bullets transcribed from the source rubric), plus `riskIfMissing`/`riskIfWeak` template sentences used to generate the risk list. `TIERS` (5-tier scale, shared with Engine 2) is declared right after. **`docWeight`s** (summing to 100): the original 8 pitch/financial docs were scaled down to 60% combined (hsgt6, pitchdeck9, execsum6, bizplan9, legalfin9, legal6, financial9, forecast6) to make room for the 8 new due-diligence docs at 40% combined (captable6, shagreement5, shlist3, prodcust7, ip4, proddata4, custdata5, useoffunds6) — reflecting that cap table/IP/product-data genuinely matter for readiness, not just narrative pitch quality. If reweighting, keep the sum at 100 and recheck every profile's tier landing (see below).
- **The overall score treats a missing document as 0, not "not applicable"**: `computeOverallScore(ds)` = `Σ docWeight × (present ? score/100 : 0)`. This is deliberate — completeness is part of the score, not just quality — so a company missing most of the 16 documents cannot reach a high score even with perfect content on what it has. `computeCompleteness()` (count present out of 16) and `computeQuality()` (weighted average of *present* docs only, renormalized) are shown as separate stats in the result panel specifically so a low score is explainable ("mediocre content" vs. "just incomplete") rather than an opaque number.
- **`docState`** (`{key: {present, score}}` for all 16 keys) is the single source of truth. Each document renders read-only as a `.doc-card` (built once from `DOC_RUBRICS` into `#criteriaList`): a status line ("Chưa có tài liệu" / "AI đã phân tích"), a score bar, a one-line AI note, and a `<details>` reveal showing that document's rubric with **live computed per-criterion scores** (`Math.round(score/100 * criterion.w)`, a proportional split — not independently scored per sub-criterion, by design, to keep 6 profiles × 16 documents authorable).
- **Radar chart** (`drawRadar()`, hand-drawn SVG polygon in `#radarSvg`, no library) — fully generic over `DOC_RUBRICS.length` (no hardcoded axis count), so it scaled from 8 to 16 axes with zero code changes when the new documents were added. 16 axes, one per document, labeled via `RADAR_LABEL` abbreviations (HSGT/Deck/ExSum/KHKD/PL&TC/HSPL/BCTC/DBTC/CapTb/HĐCĐ/DSCĐ/SP&KH/SHTT/DLSP/DLKH/KHSD). Engine 2's circular gauge (`finGaugeArc`/`finTicks`) is nested inside the *same* `#resultPanel` as a compact `.fin-sub` block, not a separate panel — the two instruments are visually distinct on purpose (radar = "which of 16 documents", circle = "one number, real math") but share one card so the page reads as one result, not two stacked tools.
- **6 sample profiles** (`PROFILES` array — GreenCart, EduPath, LogiTrack, AgriSense, MedConnect, Nexus Digital JSC) are the primary way to demo the tool. Each has a `documents` map (only keys for documents that profile actually has), each entry `{score, note}` where `note` is a one-line hand-written AI comment on that specific document. Current live scores (recompute via `computeOverallScore`, never hardcoded): GreenCart 4, EduPath 34, LogiTrack 56, AgriSense 74, MedConnect 90, Nexus 25 — landing in tiers 1/1/2/3/5/1 respectively. **Tier 4 ("Sẵn sàng gọi vốn", 75–89) is currently empty** — a deliberate, accepted tradeoff from expanding to 16 weighted documents: EduPath (household-business stage, can't legally have a cap table) and LogiTrack (seed-stage, several new docs still absent) both dropped a tier from where they landed under the old 8-document weighting, because they genuinely lack several of the new cap-table/IP/use-of-funds documents at their stage — inflating their scores to force tier-4 coverage would mean fabricating documents that contradict their own `deepDive`/`toAdd` narrative. If asked to restore full 5-tier coverage, the honest fix is a 7th profile at the tier-4 stage, not padding an existing profile's `documents`. **Nexus Digital JSC (25/100) is a deliberate exception** (not tier-tuned): built directly from the real sample AI-analysis report (`message.txt`) — only has `legalfin`/`legal`/`financial`/`forecast`/`captable`/`shagreement`/`shlist` present (the cap-table/financial-side documents the source report actually covers), scoring low overall despite `financial` itself scoring 90 and being Deloitte-audited, because none of the pitch-facing or product/customer documents exist. This demonstrates the qualitative/quantitative divergence narrative (see `buildFinancialNarrative` below) — don't "fix" its score by adding the missing docs unless asked. Profiles also carry `overview`+`deepDive`+`keyRisk`+`toAdd` narrative (unchanged shape) and — for the four later-stage profiles (LogiTrack, AgriSense, MedConnect, Nexus) — a `financials` object for Engine 2 (see below). Nexus's `financials` object is the exact dataset from `message.txt` (also reused as the `EXAMPLE`/"Tải ví dụ" data — same company, same numbers, two entry points). Clicking a `.profile-card` calls `loadProfile(id)`.
- Step 1 (upload) is a **separate, intentionally-unwired demo affordance**: drag/drop into `#dropzone`; files are only held in-memory, never uploaded or content-inspected. Clicking "Phân tích hồ sơ" runs `aiEstimateScores()`, a **fake heuristic** that marks the first `min(files.length, 16)` documents (in `DOC_RUBRICS` order) as present with jittered scores — this remains a demo stand-in, not a real model, and clears any active profile selection so the two entry points (profile picker vs. upload) don't mix state.
- **Fully read-only / automatic — no checkboxes, no sliders.** Doc-cards used to be manually toggled/dragged; that was removed because the user explicitly asked for zero manual interaction. `docState` is now only ever mutated by `loadProfile()`, `aiEstimateScores()`, or `resetDocState()` — never by the user directly. If asked to make a value user-editable again, that's a deliberate reversal of stated intent, not an oversight — confirm before restoring inputs.
- `render()` recomputes everything downstream of `docState`: radar, overall score/tier, completeness/quality stats, strengths/weaknesses (present docs scoring ≥70 / <40), risk list (missing docs' `riskIfMissing` + weak-present docs' `riskIfWeak`), missing-docs list, forecast (`computeForecast()` — assumes missing docs added at a baseline of 60 and weak present docs improved to 78), and every doc-card's live rubric breakdown.

### Engine 2 — quantitative 6-category financial calculator (Bước 3–4, "Xác thực bằng số liệu thật")

Takes user-entered financial figures (revenue, margins, balance-sheet items, cap table %, governance/legal checkboxes) and derives everything with plain arithmetic and fixed rule-based thresholds — no LLM call, no random number anywhere in `calculateFinancial()`.

- **Scoring model**: Capital Structure (20), Financial Position (20), Cash Flow (15), Governance (15), Legal Compliance (15), Valuation (15) = 100, via `bandScore()` + threshold arrays (`growthBands`, `roeBands`, `liqBands`, etc.).
- **Cross-document consistency checks**: Cap Table legal name vs. BCTC name (`nameMismatch`), Pre-money valuation vs. audited equity (P/B < 1 → critical flag), forecast-year revenue vs. current-year actual (large swings flagged). These checks were validated against a real sample AI-analysis report for a fictional company "Nexus Digital JSC" (`message.txt`) — the `EXAMPLE` object (loadable via the always-available "Tải ví dụ: Nexus Digital JSC" button) *is* that company's exact data, and it's also the `financials` object on the `nexus` profile — same dataset, two entry points into the same numbers.
- **Risks/recommendations are generated, not hardcoded**: `buildRisksAndRecos()` walks computed flags and emits templated Vietnamese sentences with real numbers interpolated, sorted by severity.
- Reuses Engine 1's `TIERS`/`tierFor`/`tierRatio`/`CIRC` directly (same 0–100/5-tier scale) rather than redeclaring them — if you ever split this back into a separate file, these need to be duplicated back too.
- IDs are `fin`-prefixed where they parallel an Engine-1 concept (`finGaugeArc`, `finScoreNum`, `finMarker`, `finTierDot/Name/Desc`, `finRiskList`, `finRecoList`, `finTicks`, `finConfidenceBadge`) — this is what lets both instruments/lists coexist inside the single merged `#resultPanel`/`.report-grid` without clobbering each other. There is deliberately no `finResultPanel` or `finScoringSection` element anymore — those were folded into `#resultPanel` (as the nested `.fin-sub` block) and a collapsible `<details class="detail-toggle">` respectively; don't recreate them as siblings.
- Financial inputs live inside `#finInputs` (itself inside a collapsible `<details id="phan-tich-tai-chinh">`); the `input`/`change` listeners are scoped to `#finInputs input` specifically (not a bare `document.querySelectorAll('input')`) so they don't fire on the upload file input.
- **Confidence badge, KPI table, and legal references** (added to more fully mirror `message.txt`'s structure) live in `renderFinancial()`/`renderFinancialEmpty()`: `computeConfidence(risks)` starts at 95 and deducts per triggered risk (critical −15, high −5, medium −3, low −1, clamped [30,97]) — it's derived from the same flags `buildRisksAndRecos()` already computes, not an arbitrary number, so keep it wired to that array if the risk logic changes. The KPI table (`#kpiTableBody`) compares 6 already-computed ratios against fixed benchmark targets (growth 25%, gross margin 50%, ROE 20%, current ratio 2.0x, debt/equity ≤1.0x, CF margin 15%) — deliberately no new input fields were added for this (e.g. no LTV/CAC/runway inputs) to avoid scope creep; the "Cần cải thiện"/"Đạt" status is direction-aware (`higherBetter` flag) since debt/equity is a lower-is-better metric. The legal references card (Thông tư 200/2014, VAS, Luật Doanh nghiệp 59/2020/QH14, Luật Chứng khoán 54/2019/QH14) is static HTML, not computed — it doesn't change per calculation, same as `message.txt`'s `references` field. Both the KPI table and the ratios table now live inside a second collapsible `<details class="detail-toggle">` alongside the refs card, not their own section.

### How they connect (this is the point of the merge — don't re-split them)

- **The two engines share one result surface, not two.** `#resultPanel` (Engine 1's radar/tier/completeness card) contains a nested `.fin-sub` block with Engine 2's gauge/tier/confidence/ratio-mini-grid; `#expertNote` (Engine 1's qualitative narrative) contains a nested `.expert-note.nested` (`#finExpertNote`) with Engine 2's narrative; the `.report-grid` under "Kết quả đầu ra chi tiết" has six columns (strengths/weaknesses/document risks/missing docs/financial risks/financial recos) in one grid, not two separate report sections. There is exactly **one** reset button (`#resetBtn`) — its click handler resets Engine 1's `docState` *and* calls `clearFinancialInputs()` for Engine 2 in the same click. Do not re-add a second reset button, a second CTA, or a second top-level result card — if a future change seems to need one, that's a signal the merge is being undone, not a normal edit.
- The 6-criteria financial score-row breakdown and the ratios/KPI/refs tables are wrapped in `<details class="detail-toggle">` (collapsed by default) rather than always-visible sections — this is what keeps the merged page "gọn" (compact) despite showing strictly more information than the pre-merge two-page version. Follow the same pattern (collapsible, closed by default) for any further detail you add rather than growing the always-visible area.
- `loadProfile(id)` is the single entry point that drives *both* engines. It always resets and rebuilds `docState`/doc-cards for Engine 1. If the selected profile has a `financials` object (LogiTrack, AgriSense, MedConnect, Nexus), it also fills every Engine-2 field and checkbox and calls `calculateFinancial()` immediately — no second click needed. If not (GreenCart, EduPath — genuinely too early-stage to have real financial statements), it calls `clearFinancialInputs()` and updates `#finContextNote` with an honest explanation ("đang ở giai đoạn quá sớm để có báo cáo tài chính chính thức") rather than fabricating numbers that would contradict the qualitative narrative. If adding a 7th profile, decide deliberately whether it gets a `financials` object — don't add placeholder financial figures just to fill the field; leave it undefined if the persona doesn't plausibly have real statements yet.
- `buildFinancialNarrative(c, risks)` — called from `renderFinancial()` — generates a `crossCheck` paragraph that reads the *current* Engine-1 score (`computeOverallScore(docState)`) and explicitly compares it to Engine 2's `c.total`: "nhất quán" if within 10 points, otherwise says which direction they diverge and why that matters. This is what makes the two scores talk to each other instead of sitting side by side independently — keep this comparison whenever either engine's scoring logic changes. The Nexus profile is the clearest demo of a *large* divergence (Engine 1 ≈ 30, Engine 2 ≈ 67) — that's expected and intentional for that profile, not a bug to reconcile.
- The financial figures for LogiTrack/AgriSense/MedConnect were hand-tuned (not just plausible-looking) so that Engine 2's computed tier roughly lands in the same tier bucket as Engine 1's score for that profile, and so specific triggered risk flags reinforce that profile's `deepDive`/`keyRisk` narrative (e.g. LogiTrack's financial data deliberately triggers the governance flags already described in its qualitative narrative). Nexus is the deliberate exception to this alignment goal (see above). If you change a profile's `documents` or `financials`, recheck whether alignment or deliberate divergence was the intent — an *unintentional* wild disagreement without narrative justification reads as a bug, not a feature.

If asked to add or reweight a document type or its sub-criteria (Engine 1) or a scoring category (Engine 2), or change tier boundaries/colors, update all synced locations: `DOC_RUBRICS`/Engine-2's weight arrays in the script, the static labels on `index.html` (`#scoring` table — now the 16 document types with their `docWeight`s, `.scale-legend`, the hero `count-up` stat labeled "loại tài liệu AI thẩm định", and the "AI đánh giá hồ sơ gọi vốn" module description — these are kept in sync with `DOC_RUBRICS` by hand, not generated, so a weight change in the script needs the matching edit in `index.html` too), `danh-gia.html`'s upload-step `.doc-checklist` (5 grouped `<ul>` lists — Giới thiệu & gọi vốn / Pháp lý & quản trị / Tài chính / Cấu trúc vốn & cổ đông / Sản phẩm & khách hàng), and every profile's `documents`/`financials` that assumed the old weights. Keep new narrative text (`overview`/`deepDive`/`keyRisk`/`toAdd`, per-document `note`, and Engine 2's generated sentences) in the same confident-advisor register as the existing content — not hedged, cites specific gaps and next actions — that tone is a deliberate choice for the pitch-competition audience this page is built for.
